# معمل المتوكل — تطبيق إدارة بيانات أطباء الأسنان

هذه نسخة بداية قابلة للتطوير لتطبيق ويب متوافق مع الهاتف (PWA). يمكن تثبيته من متصفح Android بعد نشره على HTTPS. يستخدم Firebase Authentication لتسجيل الدخول وCloud Firestore لتشارك البيانات بين المستخدمين.

## ما الذي يعمل في هذه النسخة؟
- تسجيل دخول وإنشاء حساب من الواجهة الخارجية بالبريد الإلكتروني وكلمة المرور (يتطلب تفعيل Email/Password في Firebase).
- إضافة وتعديل وحذف بيانات الأطباء.
- الحقول: الاسم، الهاتف، المحافظة، المنطقة، العنوان، حالة التواصل، موعد الزيارة القادمة، ملاحظات.
- عرض مشترك لحظي للسجلات لجميع الحسابات المصرح بها.
- بحث وفلترة حسب الحالة.
- تنبيه عند إدخال رقم هاتف موجود بالفعل.
- تصدير السجلات الظاهرة إلى CSV يفتح في Excel.
- واجهة عربية RTL متجاوبة مع الموبايل.

## التكلفة
يمكن بدء التجربة بخدمات Firebase ضمن الحصص المجانية المتاحة، واستضافة ثابتة مجانية مثل Netlify. قد تتغير الحدود أو تتطلب بعض خدمات Firebase خطة فوترة؛ راجع الأسعار الحالية قبل النشر. لا توجد رسوم مطور Android مطلوبة إذا ثبّت المستخدمون التطبيق من الموقع كـ PWA. هذا ليس ملف APK مستقلًا.

## 1) تجهيز Firebase
1. افتح https://console.firebase.google.com/ وأنشئ مشروعًا باسم مثل `almotawakel-dental-crm`.
2. من Authentication > Sign-in method فعّل **Email/Password**.
3. من Authentication > Users أنشئ حسابًا لكل شخص سيستخدم النظام. لا تضع رابط إنشاء حساب عام؛ أنشئ الحسابات بنفسك حتى تتحكم في الوصول.
4. من Firestore Database أنشئ قاعدة بيانات.
5. من Project settings > General > Your apps أضف تطبيق Web وانسخ إعدادات `firebaseConfig`.
6. انسخ `.env.example` إلى `.env.local` وأدخل إعدادات مشروعك في متغيرات `VITE_FIREBASE_*`. المتغيرات المطلوبة هي `VITE_FIREBASE_API_KEY` و`VITE_FIREBASE_AUTH_DOMAIN` و`VITE_FIREBASE_PROJECT_ID` و`VITE_FIREBASE_APP_ID`؛ أما متغيرا التخزين والرسائل فاختياريان لهذه النسخة. يقرأ `src/firebase.js` هذه الإعدادات تلقائيًا، ولا تضع القيم في ملفات المصدر. أعد تشغيل خادم التطوير بعد تغييرها.
7. افتح Firestore Rules وانشر محتوى ملف `firestore.rules` للتجربة الأولية فقط.

## 2) تشغيل المشروع على الكمبيوتر
تحتاج Node.js بإصدار حديث.
```bash
npm install
npm run dev
```
افتح الرابط المحلي الذي يظهر في الطرفية.

## 3) النشر مجانًا على Netlify
1. ارفع مجلد المشروع إلى مستودع GitHub خاص.
2. في Netlify اختر Add new site > Import an existing project، ثم اربط المستودع.
3. Build command: `npm run build`
4. Publish directory: `dist`
5. أضف متغيرات `VITE_FIREBASE_*` من `.env.example` إلى إعدادات البيئة في Netlify واجعلها متاحة أثناء البناء وفي سياقات النشر المطلوبة، ثم انشر الموقع. أي تغيير في المتغيرات يتطلب إعادة النشر. أضف الدومين المنشور إلى Authorized domains في Firebase Authentication إذا طلب Firebase ذلك.

ملف `src/firebase.js` جزء من المستودع ويجب أن يبقى موجودًا ليتمكن Vite من حل الاستيراد. ملفات `.env` المحلية مستبعدة من Git. متغيرات `VITE_*` تظهر في كود المتصفح؛ استخدمها لإعدادات تطبيق Firebase Web فقط، ولا تضع فيها مفاتيح حساب خدمة أو أسرارًا. عند غياب إعداد مطلوب تظهر شاشة الإعداد بدلًا من محاولة تشغيل Firebase بإعدادات ناقصة.

## 4) تثبيته على Android
بعد النشر على HTTPS، افتح رابط الموقع في Chrome على الهاتف > قائمة الثلاث نقاط > **Add to Home screen** أو **Install app** حسب ما يظهر. سيظهر بأيقونة على الشاشة ويفتح في نافذة شبيهة بالتطبيق. هذه النسخة لا تنتج APK مستقلًا.

## تنبيه أمني مهم قبل بيانات حقيقية
قواعد `firestore.rules` المرفقة تسمح لأي مستخدم مسجل الدخول بالوصول إلى جميع السجلات، وهذا مناسب فقط لاختبار محدود مع حسابات موثوقة. قبل التوسع، الأفضل إضافة أدوار Admin/مندوب، ومنع الحذف لغير المدير، وتسجيل سجل تدقيق للعمليات، ووضع قواعد تحقق للحقول. إعدادات Firebase الموجودة في تطبيق الويب ليست كلمة سر؛ الأمان الحقيقي يعتمد على Authentication وقواعد Firestore. لا تخزن كلمات المرور في قاعدة البيانات ولا تشارك حسابًا واحدًا بين المندوبين.

## تحسينات مقترحة للمرحلة الثانية
- حساب مدير يدير أدوار الحسابات ويوقف/يفعّل المندوبين من لوحة الإدارة.
- سجل مستقل لكل زيارة (بدل حقل ملاحظات واحد).
- صلاحيات حسب الدور والمنطقة.
- نسخ احتياطي دوري وتصدير كامل.
- إشعارات تذكير للزيارات القادمة.
- تجهيز APK باستخدام Capacitor أو Android Studio إذا كان ملف APK شرطًا أساسيًا.

## ملاحظة
هذه نسخة أولية تقنية وليست مراجعة أمنية أو نظامًا إنتاجيًا مكتملًا. اختبرها ببيانات تجريبية أولًا، ولا تضع بيانات حساسة قبل ضبط الصلاحيات.


## إعداد واجهة إنشاء الحساب
أضفنا تبويب "إنشاء حساب" في شاشة الدخول. أي شخص يستطيع الوصول إلى الرابط قد يتمكن من إنشاء حساب إذا كان تسجيل البريد الإلكتروني مفعّلًا. إذا كان التطبيق للمندوبين المعتمدين فقط، لا تنشر التسجيل الذاتي في صورته الحالية؛ الأفضل إخفاء إنشاء الحساب العام وإنشاء الحسابات يدويًا من Firebase Authentication، أو بناء دعوات/قائمة سماح وصلاحيات أدوار قبل الاستخدام الفعلي.


## نظام الأدوار والتحكم (مدير ومندوب)
- أي شخص يسجل من الواجهة يحصل على دور `rep` (مندوب) فقط.
- يظهر تبويب "إدارة الحسابات" للمدير فقط؛ يقدر يرقّي حسابًا إلى مدير، أو يعيده مندوبًا، أو يوقفه ويعيد تفعيله.
- عند إيقاف الحساب، تمنع قواعد Firestore وصوله إلى بيانات الأطباء حتى لو بقي تسجيل الدخول مفتوحًا.
- لا يمكن لأي مستخدم ترقية نفسه لأن إنشاء ملف المستخدم يسمح بدور `rep` فقط، وتعديل الأدوار محصور بالمدير في قواعد Firestore.

### تعيين أول مدير مرة واحدة
1. سجّل حسابك من الواجهة كالمستخدم العادي أولًا.
2. من Firebase Console > Authentication > Users انسخ UID الخاص بحسابك.
3. افتح Firestore Database وأنشئ مجموعة `users` (إن لم توجد)، ثم مستندًا يكون معرّفه **UID نفسه حرفيًا**.
4. أضف الحقول:
   - `email` (string): بريد حسابك.
   - `role` (string): `admin`
   - `active` (boolean): `true`
   - `createdAt` (timestamp): الوقت الحالي.
5. انشر قواعد `firestore.rules` الموجودة في المشروع.
6. سجّل الخروج ثم الدخول من جديد، وستظهر لك إدارة الحسابات.

**تنبيه:** تعيين أول مدير يتم يدويًا من Firebase Console مرة واحدة فقط. لا تترك قواعد Firestore القديمة مفتوحة بعد النشر.
